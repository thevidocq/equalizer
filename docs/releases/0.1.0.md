# Equalizer 0.1.0 — first stable prototype

The first release you can install and use end to end on one VPS with Docker
Compose. Install: `INSTALL.md`, with `git checkout v0.1.0` and
`EQ_VERSION=0.1.0`.

## What it does

Equalizer sits between visitors and old web applications. The legacy server
is no longer reachable from the Internet: a connector on its network opens
an outbound tunnel, and the gateway serves the site on its own domain,
rebuilding every request. The site looks and works as before.

| Part | In this release |
| --- | --- |
| Gateway | Multi-site by host name; faithful rendering; precise entries (routes, sealed forms, JSON APIs, assets) with typed values; **areas** that serve whole sections as they are, admin included, still rebuilt (forms, multipart, JSON, XML without DOCTYPE, text); file uploads with real type, size and image rebuild; authorisation per object (`owned_by_user`, from pages, redirects and JSON); sessions with legacy cookies kept server-side; optional login with the organisation's identity provider (OIDC, off by default); rate limits and behaviour rules |
| Connector | One per server, outbound tunnel only, local allowlist, virtual hosts |
| Relay | Several replicas with handover, tenant and destination checks |
| Panel | Tenants and email invitations, platform/tenant privacy, sites and connectors, maps with editor, CMS templates (WordPress, Joomla, Drupal, Moodle, generic), import/export, review aid, approval, signing and rollback, discovery (with or without the tenant's AI), isolation check, status, logs, login settings, activity |
| Agent | Read-only discovery through the connector, anonymous and with a test account; CMS fingerprint; map proposals with the whole-site area; IDOR protection for JSON APIs; optional AI review of map versions |
| Operations | Caddy with on-demand TLS, Postgres, Redis, Vector, Loki, Grafana; images on GHCR for every release |

## Compatibility with real sites

- The visitor's real address reaches the legacy application
  (`X-Forwarded-For`, `X-Real-IP`) and shows in the Logs and their CSV
  export; behind Cloudflare set `EQ_BEHIND_CLOUDFLARE=true`.
- Session cookies stay on the gateway; the others (language, consent,
  cookies written by the page's scripts) work as on the legacy site.
- "Remember me" on the legacy login keeps the visitor signed in, up to
  `remember_days` (default 30).
- Application headers pass both ways (`X-WP-Nonce`, `X-CSRF-Token`,
  `X-WP-Total`…), and HTTP logins (`Authorization`, `WWW-Authenticate`).
- Live updates (`text/event-stream`) are streamed.
- Uploads are streamed through a temporary file, up to 1 GB; the limit is a
  template parameter (**Max upload (MB)**, default 50).
- Pages in Western, Central European and Cyrillic charsets.
- Template entries accept any legitimate value (slugs in any language,
  longer searches and comments).

## Security properties

- The legacy application is never exposed: only the connector reaches it.
- No client byte reaches it as written: path, query, headers and bodies are
  parsed and written again; malformed requests, XML entities, NUL bytes and
  unknown binary bodies are refused before it.
- Its cookies, internal host and error details never reach the browser.
- Maps are signed; the panel checks every version with the gateway's own
  rules before it can be published.
- Access control stays with the legacy application: Equalizer does not
  decide who may do what, except where a map adds a rule.

## Known limits

- Tested with automated tests and fake services (identity provider, Loki,
  relays), not yet against real sites in the lab: expect fixes in 0.1.x.
- WebSocket is not served (501), nor request bodies that are neither forms,
  JSON, XML nor text (415): both show in the Logs.
- No virus scanning of uploads (left to the legacy server's security stack).
- Discovery does not run JavaScript: APIs of single-page apps come from the
  map, not from crawling.
- Not available yet: SIEM forwarding, one legacy account per user behind
  OIDC, single sign-on to the panel, capacity settings from the panel
  (replicas are set in `.env`), alerts for known CMS vulnerabilities,
  Kubernetes.
