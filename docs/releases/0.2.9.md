# Equalizer 0.2.9 — discovery finds every file the site loads

Install: `INSTALL.md`, with `git checkout v0.2.9` and `EQ_VERSION=0.2.9`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.9`. Updating from
0.2.8: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. No database
change, no new setting.

## Changes you will notice

- **No more types to add by hand.** Discovery now proposes the types of the
  files it finds under asset prefixes already in the map: a video under a
  prefix that listed only images gets `video/mp4` in the proposed map.
- **Files named in stylesheets are found.** Discovery reads the site's
  stylesheets (and those they import), `<style>` blocks and `style=""`
  attributes, so fonts (`@font-face`) and background images are in the map.
- **Lazy and responsive images, video posters.** `srcset`, `data-src` and
  similar attributes, a video's `poster`, `embed`, `object` and `track` are
  studied.
- **What visitors miss is learned.** When the gateway refuses a file for its
  type or size, it tells discovery; the next discovery checks the file on
  the site and proposes it if the site really serves it. One visitor is
  enough. A file whose content does not match its type is never proposed.
- **More file types known:** `.otf`, `.webm`, `.ogv`, `.m4v`, `.mp3`,
  `.m4a`, `.ogg`, `.wav`.

## What to do

- Run discovery again on sites already protected and publish the proposed
  map: the report lists the types added to existing prefixes.

## For operators

- After the update run `deploy/compose/check.sh`.
