# Equalizer 0.2.14 — the checks hold when a request steps aside

Install: `INSTALL.md`, with `git checkout v0.2.14` and `EQ_VERSION=0.2.14`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.14`. Updating from
0.2.13: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. No
migration, no new setting. Run a discovery on each site afterwards: the
agent's maps are a little more precise (below).

## Why

An efficacy study measured what reaches a real WordPress through
Equalizer (`docs/efficacy.md`). Typed values (an id, a page number, an
email) were always refused when attacked, but adding one unknown parameter
(`/?p=1' OR '1'='1&zz=1`) sent the whole request to the site area, which
does not check values: 0 attacks out of 125 were blocked that way.

## Changes you will notice

- **One extra parameter no longer carries an attack.** A request with a
  parameter the map does not know is still served (so the site keeps
  working exactly as before), but the parameters the page declares are
  checked first. Measured on five sites: 500 of 500 such attacks blocked,
  every page still the same (161 of 161).
- **Page names with injection characters are refused**: angle brackets,
  braces, backticks, pipes, backslashes and quotes (an apostrophe inside a
  word, as in `l'evento`, is fine) in a page's name never reach the site.
- **Disguised parameters are checked too**: `page.id`, `page id` or
  `page_id[]`, which PHP reads as `page_id`, are checked as `page_id`.
- **Unknown parameters reach the report.** Because the request used to
  leave the page entirely, the gateway never reported them; now it does,
  and the discovery adds those visitors really use, with the values the
  site offers (0.2.13).
- **WordPress comments**: the name and website fields refuse markup, and
  the website must be an http(s) address (new discoveries).
- **More precise maps for sites with `.php` pages**: the agent no longer
  gives a page's parameters to a route that never serves that page (the
  intranet's `notice.php?id=` was never checked). On phpBB and MediaWiki
  the share of pages served by precise entries goes from about 5% to all
  but one.

- The efficacy study is part of the lab (`lab/e2e/efficacy/`) and runs
