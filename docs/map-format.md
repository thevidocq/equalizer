# Map format

The map is the gateway's single source of truth: **whatever is not declared
does not exist**. Schema: [`schema/map/gateway-map.schema.json`](../schema/map/gateway-map.schema.json).
Full example: [`schema/map/examples/permits-portal.yaml`](../schema/map/examples/permits-portal.yaml).

## Principles

- **Equalizer is in between, it does not decide**: the whole site is served
  as the legacy site serves it, admin included (areas); access control stays
  with the legacy application. What Equalizer removes is the direct contact
  and every byte the client wrote.
- **Only what is in the map exists**: a path outside every entry and area is
  404 and the legacy application is not contacted. With the `/` area the
  whole site is in the map.
- **Rebuilding**: every request to the legacy application is generated by the
  gateway: from `legacy_request` for precise entries, from the parsed path,
  query and body for areas.
- **Strict types**: every input value has a type and constraints. `text` needs
  `rules`; `file` needs `mime` and `max_size_kb`.
- **Authorisation in the gateway** (`roles`, `authz`, `scope`).
- **Provenance**: `origin` (agent/human), `confidence`, `risk`.
- **Immutable versions**, signed on publication.
- **Secrets outside the map**: only `vault://` references.

## Sections

| Section | Contents |
| --- | --- |
| `meta` | Schema, tenant, app, version, status, author, approver, `public_domain` (set by the panel: the host the map is served on) |
| `legacy` | `base_url`, `reach` (connector or direct, allowed destinations), login, expired session, error detection |
| `roles` | Role of unauthenticated visitors (`anonymous`), authentication on the gateway, legacy account per role |
| `defaults` | Rate limits, budget towards the legacy app, cache, string constraints, error template |
| `types` | Reusable types (`permit_id`, `tax_code`, ...) |
| `routes` | Read-only pages (`GET`): request to the legacy app, `render`, links, permissions |
| `forms` | Writes: typed fields, rebuilt request, outcome, limits |
| `flows` | Sequences of forms with server-side state |
| `api` | JSON endpoints for dynamic parts |
| `compat` | Historical URLs, served or redirected |
| `callbacks` | Inbound calls from third parties, with verification |
| `assets` | Static files served by prefix (CSS, images, scripts, fonts) with the allowed types |
| `areas` | Whole sections served as they are (`/` for the whole site), rebuilt but not typed; precise entries take precedence |
| `external_links` | Allowed external domains |
| `behavior` | Behavioural thresholds |

## Reaching the legacy site

```yaml
legacy:
  base_url: https://permits.example-city.gov   # the site as its web server knows it
  reach:
    mode: connector
    connector_id: cn-srv-web01                 # one connector per server, of your tenant
    address: "127.0.0.1:8443"                  # where to connect (optional)
    allow: ["127.0.0.1:8443"]
```

- The host of `base_url` goes in the `Host` header and in TLS SNI: the web
  server picks the right virtual host. Links in pages that point to it are
  recognised as internal.
- `address` (optional) is where the connection actually goes, when it is
  not the host of `base_url`: a site moved to an internal listener, or an
  IP shared by several virtual hosts. It must be in `allow`.
- One connector serves every site of the servers it reaches. The panel
  refuses a map whose `connector_id` is not a connector of the same tenant,
  and the relay refuses it again at every request.
- `mode: direct` (the gateway connects itself) is accepted only towards the
  destinations the platform allows (`EQ_DIRECT_DESTINATIONS`, e.g. lab
  apps); customer sites always use a connector.
- `client_ip: forwarded` (default) sends the visitor's real address to the
  legacy application in `X-Forwarded-For` and `X-Real-IP`, as a reverse
  proxy would: its own logs, bans and geolocation keep working. The address
  is the one the gateway saw (Caddy, or `CF-Connecting-IP` when
  `EQ_BEHIND_CLOUDFLARE=true`), never the header the browser sent.
  `client_ip: none` sends nothing. The same address is in Equalizer's logs
  (`src_ip`) and in their CSV export.

## Rendering

- `render: faithful` (default): the legacy HTML, transformed, with an
  identical look.
- `render: template`: a new view generated by the gateway; requires
  `template` and `extract`.

## Links and assets in pages

Faithful rendering rewrites every internal URL found in a page (`href`,
`src`, `action`, `srcset`, `<base>`, ...):

1. if it matches a route's `links` or a `compat` entry, it becomes the public
   route;
2. otherwise, if it matches the `legacy_request` of a GET route (same path,
   same query keys), it becomes that route: often there is no need to declare
   `links`;
3. if it is under an `assets` prefix, it keeps the same path;
4. otherwise it becomes a relative path, which the gateway rejects (404) and
   counts as an unmapped URL.

The legacy host never appears in the page. External URLs stay unchanged.
Assets are served only if the legacy `Content-Type` is among the prefix's
`types`; raster images are also checked against their real content. The
asset query string is never sent to the legacy application.

## Forms

A form is recognised in a legacy page by inverting its `legacy_request`: the
`<form method="post">` must post to the same path and query, and the hidden
inputs named in the body as `{{params.x}}` give the public action's
parameters. Example:

```yaml
forms:
  - id: permit_supplement
    route: /permits/{id}/supplement
    params: { id: { type: permit_id } }
    fields:
      message: { type: text, max_length: 1000, rules: [no_html] }
    legacy_request:
      method: POST
      path: /permits/supplement.do
      form:
        permitId: "{{params.id}}"   # read from the page's hidden input permitId
        text: "{{fields.message}}"  # the page's "text" input is renamed "message"
        state: "{{hidden.state}}"   # hidden input kept server-side
        kind: "SUP"                 # fixed value
    success: { body_contains: "Supplement recorded" }
    on_success: { redirect: permit_detail }
```

When the page is rendered:

- **every** hidden input of a POST form is removed from the page; the values
  the map uses (`{{params.x}}`, `{{hidden.x}}`) are sealed, with the page's
  charset, into a single `_eq_token` field (AES-256-GCM, valid two hours);
- the action becomes the public route, inputs take the public field names;
- the token is bound to a browser cookie (`__Host-eq_form`): a token taken
  from another browser is rejected (CSRF).

On submission the gateway accepts only `application/x-www-form-urlencoded`
bodies up to 1 MiB, rejects cross-site requests (`Origin`,
`Sec-Fetch-Site`), checks that the token belongs to this form and this
record, validates the declared fields (undeclared ones are dropped),
re-encodes every value into the legacy charset (a character the charset
cannot hold is rejected) and rebuilds the request. If `success` passes and
`on_success.redirect` names a route whose URL can be built from the form's
parameters, the visitor gets a 303 to it; otherwise the legacy answer is
shown with faithful rendering.

Not supported yet: `file` fields and `files` (the form answers 503), the
`cookie` success check (login), per-form rate limits. POST forms that match
no declared form keep working visually but post to a path the gateway
rejects.

## Login and sessions

With `roles.auth.provider: passthrough` the legacy login page stays exactly
as it is. The login is a declared form with `session.start`:

```yaml
forms:
  - id: login
    route: /login
    roles: [guest, citizen]
    fields:
      username: { type: string, max_length: 64, charset: "[A-Za-z0-9._@-]" }
      password: { type: password, max_length: 128, rules: [no_template_meta] }
    legacy_request:
      method: POST
      path: /login.do
      form: { j_username: "{{fields.username}}", j_password: "{{fields.password}}" }
    success: { cookie: JSESSIONID, not_contains: "Invalid credentials" }
    session: { start: citizen }
    on_success: { redirect: permits_list }
routes:
  - id: logout
    path: /logout
    roles: [citizen]
    legacy_request: { method: GET, path: /logout.do }
    session: { end: true }
```

How it works:

- **Private legacy cookies never reach the browser.** A cookie the legacy
  app marks `HttpOnly`, or whose name looks like a session or a login
  (`PHPSESSID`, `wordpress_logged_in_*`, `MoodleSession`, anything with
  `sess`, `auth`, `token`, `user`, `admin`, `role`…), stays on the gateway:
  it creates a session (often already on the login page), keeps the cookie
  there and adds it to every rebuilt request. The browser holds
  `__Host-eq_session`, a random id, and can never send a cookie of those
  names.
- **Login answers.** Every cookie set by the answer to a `session.start`
  form is private, whatever its name.
- **Other legacy cookies work as on the legacy site.** Language, consent,
  CSRF tokens the page's scripts read: they go to the browser (`Secure`,
  `SameSite=Lax` at least), scripts read and write them, and they come back
  to the legacy application rebuilt: at most 50, names and values from a
  safe character set, privilege-like names dropped.
- **Remember me.** When the legacy login sets a persistent private cookie
  (the "keep me signed in" box), the gateway session lives as long as that
  cookie, up to `defaults.session.remember_days` (default 30, 0 turns it
  off): the session cookie is kept when the browser closes and the
  absolute limit no longer applies. Logging out or a legacy expiry ends it.
- **Role.** A visitor has the `roles.anonymous` role until a form with
  `session.start` succeeds; then the session gets that role and a **new id**
  (no session fixation).
- **Success check.** `success.cookie` requires that the session holds that
  legacy cookie; `not_contains`, `body_contains`, `status` and
  `redirect_to` work as for any form. A failed login changes nothing.
- **Legacy expiry.** When `legacy.session_expired` matches (redirect to
  `redirect_to`, one of `status`, or `body_contains`), the role and the
  legacy cookies are dropped.
- **Logout.** A route or form with `session: { end: true }` deletes the
  session after the legacy answer.
- **Limits.** `defaults.session.idle_minutes` (default 30) and
  `absolute_hours` (default 12, restarted at login), except for a
  remembered session (above).
- **Storage.** Redis (`EQ_REDIS_URL`), shared by every replica; key = SHA-256
  of the id, content encrypted with AES-256-GCM. Pages of a session are sent
  with `Cache-Control: private, no-store`. If the store is unreachable,
  visitors are anonymous (restricted pages answer 403) and logins answer
  503.
- **`password` type.** Any printable character (the string defaults do not
  apply), at most 128 by default, never logged; like `text`, it needs at
  least one rule.

Not handled yet: legacy cookies are kept by name only (`Path` and `Domain`
are ignored), OIDC in front of the legacy login, per-user legacy accounts
from the vault.

## Rate limits and behaviour rules

Counters live in Redis and are shared by every replica (in process without
`EQ_REDIS_URL`). Keys hold only hashes of IPs and sessions.

- **`defaults.rate_limit`** applies to every page and form (not to assets);
  a route's or form's `rate_limit` applies on top. Values: `N/s`, `N/min`,
  `N/hour`, `N/day`, fixed windows.
- **Dimensions:** `per_ip`; `per_session` (the IP when there is no session);
  `per_user` (the session after login, the IP before).
- Over the limit: **429** with `Retry-After`, event `ratelimit.hit`; the
  legacy app is not contacted.
- **`defaults.legacy_budget.max_rps`** caps requests per second towards the
  legacy app across replicas (503 above it); `max_concurrency` stays per
  replica.

Behaviour rules (`behavior`):

| Signal | Counts |
| --- | --- |
| `distinct_param_values` | Distinct values of `param` (path parameter or query) on the route — enumeration |
| `failed_logins` | Submissions of a `session.start` form whose success check failed — brute force |
| `request_rate` | Requests to the route (or to every entry without `route`) |
| `missing_predecessor` | Accepted, not applied yet (logged at map load) |

When `threshold.count` is reached within `threshold.window` for the same
subject (`per`: `ip`, `session`, `user`):

- `throttle` (and, for now, `challenge`): 429 on that route until the window
  ends;
- `block`: 403 on the **whole site** until the window ends (event
  `request.blocked`, reason `behavior_block`);
- `alert`: one `behavior.alert` event when the threshold is crossed.

On routes the request that crosses the threshold is already refused; on
forms (the legacy app has answered) the rule applies from the next request.
If Redis is unreachable, limits are not applied (fail open) and the error is
logged every 10 seconds at most.

## JSON APIs

For the parts of a site that JavaScript loads in the background.

```yaml
api:
  - id: permit_list
    path: /api/permits          # the same path the site's JavaScript calls
    method: GET
    roles: [citizen]
    query: { page: { type: int, min: 1, max: 500, required: false } }
    legacy_request: { method: GET, path: /rest/permits, query: { p: "{{query.page}}" } }
    response:
      list: true
      path: data.items          # where the list is in the legacy JSON
      fields: { id: { type: int }, title: { type: string, max_length: 200 } }
  - id: permit_save
    path: /api/permits/{id}
    method: PUT
    roles: [citizen]
    params: { id: { type: permit_id } }
    body: { title: { type: string, max_length: 200 }, urgent: { type: bool, required: false } }
    legacy_request:
      method: PUT
      path: /rest/permits/{{params.id}}
      json: { title: "{{body.title}}", urgent: "{{body.urgent}}" }
    response: { fields: { id: { type: int }, title: { type: string } } }
```

- The body must be a JSON object with `Content-Type: application/json`:
  an undeclared key, a nested object or a value of the wrong type is a
  400. Values are checked with the same types as forms.
- `legacy_request.json` is rebuilt from scratch: `"{{body.urgent}}"` becomes
  `true`, an `int` becomes a number, an absent optional value is left out.
- Only `response.fields` reach the browser, each with its declared type; a
  value of another type is dropped. A legacy error never shows its body:
  the client gets `{"error": "unavailable"}`, `not_found` or `forbidden`.
- Writes (`POST`, `PUT`, `PATCH`, `DELETE`) are refused when the browser
  says they come from another site (`Origin`, `Sec-Fetch-Site`).

## File uploads

```yaml
fields:
  attachment: { type: file, mime: [application/pdf, image/png], max_size_kb: 5120, required: false }
legacy_request:
  method: POST
  path: /upload.do
  form: { title: "{{fields.title}}" }
  files: { attachment: "{{fields.attachment}}" }
```

- The real type is read from the bytes (never the file name or what the
  browser says) and must be in `mime`; the size is bounded by `max_size_kb`.
- `scan: cdr` rebuilds images (PNG, JPEG, GIF) from their pixels, dropping
  metadata and anything appended; it is allowed only when every type in
  `mime` is an image. Equalizer does not scan for viruses: leave that to the
  security stack around the legacy application.
- The legacy application receives a new random file name; undeclared file
  fields are refused.

## Authorisation: who may open which object

An allowlist checks the shape of `/permits/43`, not whose permit it is. For
pages and APIs that show one person's objects, add a rule per role:

```yaml
  - id: permit_detail
    path: /permits/{id}
    roles: [citizen]
    params: { id: { type: permit_id } }
    authz:
      citizen: { check: owned_by_user, target: params.id }
```

- `owned_by_user`: the session may open only the values the legacy site
  itself showed it, in links of its pages, in its redirects, or in the
  fields of its JSON answers named in `response.issues` (below). If "My
  permits" lists 5 and 7, `/permits/9` answers 403 (`authz_not_owned`), even
  though 9 exists. The values live in the session (at most 2000 per target)
  and go when the legacy session ends.
- `never`: the role may not open the entry; `always`: no check.
- Single-page apps load their lists as JSON. The API that returns the list
  says which field carries the ids and where they open:

  ```yaml
  - id: permits_list
    path: /api/permits
    response:
      list: true
      path: items
      fields: { id: { type: int }, title: { type: string } }
      issues: { id: permit_get.params.id }   # entry.ns.name
  ```

  The entry named must have an `owned_by_user` rule on that target, and the
  field must be in `fields`; otherwise the map does not load. Discovery
  proposes both when a GET list API and a GET detail API (`/api/x` and
  `/api/x/{id}`) share an id of the same type, unless a person already chose
  another rule for the detail. The review aid
  flags new `issues` (`issues_added`).
- Forms need no rule: their parameters travel sealed in the form token.
- The review aid flags new pages with personal-looking paths and no rule,
  and any rule removed.

## Rollback

A version that was published before can be published again at once (Map →
the version → **Roll back to this version**, approvers and administrators):
it was approved when it first went live, and its signed document is the
same.

## Login with the identity provider (OIDC)

Off by default: without `roles.auth`, or with `provider: passthrough` or
`none`, visitors use the site's own login as today. With `oidc` the gateway
logs them in with the organisation's identity provider first (Entra ID,
Google, Okta, Keycloak…), with the authorization code flow and PKCE:

```yaml
roles:
  anonymous: guest
  list: { guest: {}, staff: {}, manager: {} }
  auth:
    provider: oidc
    issuer: https://login.microsoftonline.com/<tenant id>/v2.0
    client_id: 7d2a91c4-…
    scopes: [openid, email, profile]   # openid is always added
    groups_claim: groups               # claim with the user's groups
    roles:                             # first match wins; * = every user
      - { group: Portal managers, role: manager }
      - { group: Portal staff, role: staff }
    required: true                     # false: anonymous until /.eq/oidc/login
```

- The role comes from the user's groups, never from the browser or from the
  legacy login; a user in no listed group gets 403.
- The gateway checks the ID token itself: signature with the provider's
  keys (RSA or EC, never `none` or HMAC), issuer, audience, expiry, nonce;
  the login state is tied to the browser's session and expires in 10
  minutes; after the login the session gets a new id.
- Its own paths: `/.eq/oidc/login`, `/.eq/oidc/callback` (to register in
  the provider as `https://<public domain>/.eq/oidc/callback`),
  `/.eq/oidc/logout`. Pages answer with a redirect to the provider, APIs and
  writes with 401.
- The client secret is not in the map: it is saved in the panel (Site →
  Login), encrypted, and given only to the gateways. Without one the client
  is public and relies on PKCE.
- The legacy site still sees its own login, if it has one: one legacy
  account per user is not available yet.
- The review aid flags turning it on or off, another issuer, `required:
  false` and a `*` group.

## Import and export

Every version can be downloaded as YAML (**Download as YAML**), without the
meta the panel owns. **New version → Import a map file** loads a YAML or
JSON map into the editor, for a backup, a move from a test site to the real
one, or a site like another: tenant, site and domain are set from the site
it is imported into, and the draft gets the same checks (schema, reach,
connector of the tenant) and approval as any other. A file is never
published as it is.

## Areas: the whole site, admin included

```yaml
areas:
  - id: site
    prefix: /                 # the whole site; /wp-admin/ for a section only
    methods: [GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS]  # default GET, HEAD, POST
    # roles: [...]            # absent: every role, like the legacy site
    # max_body_kb: 51200      # default
    # charset: iso-8859-1     # legacy charset of form values, default utf-8
```

A request that no precise entry (route, form, API, asset) matches goes to
the area with the longest prefix. The answer is the legacy site's: same
status, same content, pages rendered like any other, downloads streamed,
redirects to other sites passed on. Equalizer still sits in between:

- the legacy application is never reached directly, and its cookies stay on
  the gateway;
- the path is checked (no control characters, no `..`), the query and the
  body are parsed and written again: urlencoded and multipart forms (files
  included, names cleaned), JSON (same order, same numbers), XML (a DOCTYPE,
  where external entities live, is refused) and plain text; any other body
  is 415;
- request headers are rebuilt from a list: `Accept`, `Accept-Language`,
  `Range`, cache validators, `Authorization` (Basic, Bearer, Digest and
  Token, for sites with an HTTP login), the application's own `X-*` headers
  (e.g. `X-WP-Nonce`, `X-CSRF-Token`; at most 30, printable values; never
  those a server may trust as set by a proxy: client address and host
  (`X-Forwarded-*`, `X-Real-IP`…), rewritten URL (`X-Original-URL`), method
  override (`X-HTTP-Method-Override`), identity (`X-Remote-User`,
  `X-Auth-User`…), internal sub-requests); `Referer` and `Origin` become
  the legacy site's;
- the answer keeps the application's `X-*` headers (e.g. `X-WP-Total`),
  `Link`, `Retry-After` and `WWW-Authenticate`; headers that reveal the
  platform (`X-Powered-By`, `X-AspNet-Version`…), internal paths
  (`X-Accel-Redirect`, `X-Sendfile`), debugging or the legacy address are
  dropped;
- uploads (multipart) are rebuilt part by part into a temporary file, never
  held in memory, up to `max_body_kb` (at most 1 GB); other bodies up to
  64 MB;
- live updates (`text/event-stream`) are passed event by event, up to 10
  minutes per connection (browsers reconnect by themselves); WebSocket is
  not supported yet (501);
- pages in Western, Central European and Cyrillic charsets
  (`windows-125x`, `iso-8859-*`, `koi8-r/u`, `ibm866`) are converted to UTF-8;
  the charset is learnt from the site's pages and used for its forms;
- rate limits and form tokens apply only to precise entries; behaviour
  rules apply everywhere.

Precise entries add what areas cannot: typed values, sealed forms,
authorisation per object. Discovery adds them where it can and always keeps
the `/` area, so nothing of the site is left out.

## Templates

When a site is protected its CMS can be chosen (WordPress, Joomla, Drupal,
Moodle, or a generic site): the first draft starts from a template with the
`/` area (the whole site works at once, admin included) and precise entries
for its pages, assets and forms. The page slugs refuse the admin names
(`deny`), so `/wp-admin/` goes to the area instead of `/{slug}/`.

The precise entries of templates are loose on purpose: slugs take any
letter of any language, searches up to 200 characters, plain strings up to
1000; they still refuse markup and template sequences. The largest upload
is a parameter of the template (**Max upload (MB)**, default 50, at most
1024): it sets `max_body_kb` of the areas and the size of files served from
upload folders.

## Field types

| Type | Constraints | Default risk |
| --- | --- | --- |
| `int` | `min`, `max` | low |
| `enum` | `values` | low |
| `bool`, `date` | fixed format | low |
| `string` | `pattern` or `charset`, `max_length` | medium |
| `email` | format, `max_length` | medium |
| `text` | `charset`, `max_length`, `rules` (required) | high |
| `password` | `max_length`, `rules` (required); never logged | high |
| `file` | `mime`, `max_size_kb` (required), `scan: cdr` | high |


A type or a field can list refused values in `deny` (compared without
case): `slug: { base: string, pattern: "^[a-z0-9-]+$", deny: [wp-admin, admin] }`.
## Rules for text fields

| Rule | Rejects |
| --- | --- |
| `no_html` | `<`, `>`, numeric entities `&#` |
| `no_sql_meta` | `--`, `/*`, `*/`, `;`, `\`, `"`, `` ` ``, NUL; the apostrophe is allowed only between two letters (`O'Brien`) |
| `no_template_meta` | `<?`, `?>`, `<%`, `%>`, `${`, `#{`, `{{`, `}}` |

An unknown rule makes the map impossible to load. Undeclared query
parameters are dropped; repeated ones are rejected. Without
`roles.anonymous` no page is public.

## Lifecycle

`draft` → `in_review` → `approved` → `published` → `retired`.

| Change class | Examples | Approval |
| --- | --- | --- |
| Widens the surface | New route/form, new role, less restrictive field, new `text`/`file` | Always, by a person other than the author |
| Narrows the surface | Route removed, tighter constraint | Automatic in automatic mode |
| Rendering only | Selectors, texts | Automatic in automatic mode |
| Behaviour and limits | Thresholds, rate limits, budget | Automatic if more restrictive |

The class is computed by the system from the diff, not declared by the
agent. An imported map arrives as a proposal and follows the same rules.

## Signature

The gateway reads a `SignedMap` document (see `schema/api/panel-api.yaml`):
`payload` is the base64 of the compact map JSON, `signature` is the Ed25519
signature of those bytes. The gateway only accepts maps with a valid
signature, `meta.schema` equal to `gateway-map/1.0`, `meta.status` equal to
`published` and `version` equal to `meta.version`. In the prototype maps are
signed with `eqtool sign`; later panel-api will do it.

## Notes

- In YAML the key `on` is read as a boolean: the map uses `target` instead
  (e.g. `authz.citizen.target: params.id`).
