# Equalizer 0.2.4 — onboarding, direct mode by name, delete a site

Install: `INSTALL.md`, with `git checkout v0.2.4` and `EQ_VERSION=0.2.4`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.4`. Updating from
0.2.3: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. One migration
(`0024`) runs on start: it makes a site's rows cascade so a site can be
deleted; nothing to do by hand.

## Changes you will notice

- **A new site starts with Discovery, then the map.** Adding a site now
  opens **Discovery**, where the agent explores the site and proposes a
  draft map for you to review on the **Map** tab — instead of opening an
  empty map that then had to trigger discovery. The tab order is
  **Discovery → Map → Isolation → Certificate → Login**. You can still
  build a map by hand from a template on the Map tab.
- **Delete a site.** An administrator can delete a site from its header
  (**Delete site**). It asks you to type the site's name to confirm, and
  removes the map, connectors, discoveries, verifications and certificate
  with it. The gateway stops serving it and its connector can no longer
  reconnect.
- **Reach a site directly by name.** Direct mode (no connector) now accepts
  a name, not only a public IP — useful for a site behind a CDN whose IP you
  should not pin. Enter `origin.example.com:443` or `203.0.113.10:443`.
  Equalizer connects only to a public address: a name that resolves, now or
  by later rebinding, to a private or reserved address is refused — at save
  time and again at the moment of connection — so it can never reach the
  platform's own network. In direct mode the original site must still accept
  only Equalizer's addresses, or visitors could skip the gateway; **Site →
  Isolation** checks it.
- **One spinner in Discovery.** The running discovery no longer shows two
  spinners at once; the live one, with the page count, stays in the report.
- **Mobile "Protect a site" fixed.** Opening "Protect a site" from the phone
  menu now reliably shows the dialog (it was dismissed with the menu in
  0.2.3).

## For operators

- After the update run `deploy/compose/check.sh`.
- Migration `0024` switches the app-referencing foreign keys that were not
  already `ON DELETE CASCADE` to it, so deleting a site removes everything
  that belongs to it in one step. It touches constraints only, no data.
