# Equalizer 0.2.26 — slugs that stay closed, pages that change by themselves

Install: `INSTALL.md`, with `git checkout v0.2.26` and `EQ_VERSION=0.2.26`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.26`. Updating from
0.2.25: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. No
migration, no new setting.

## Fixed

- **Page, category and tag slugs let SQL and shell characters through**
  (the "Still open" list of a WordPress site). The CMS templates' slug
  refused only a few characters (`/ . < > { } " ' \`): spaces, `;`, `|`,
  `$( )` passed. A slug is now letters and digits of any alphabet
  (`/tag/επίπεδο/`, `/コーヒー/` included), combining marks, `-` and `_`;
  never quotes, spaces, dots or slashes, and never characters that look
  like ASCII (fullwidth `ａｄｍｉｎ`, `𝐚𝐝𝐦𝐢𝐧`, `ﬁ`, the modifier apostrophe
  `ʼ`), which a legacy stack could fold. MediaWiki titles also take `( ) , : !`. A page whose
  address has other characters is served by the area.
- **The discovery grouped Greek or accented slugs badly**: it read path
  segments encoded, so `/tag/%ce%b5…/` stayed a route of its own and kept
  the Latin tags from becoming `/tag/{slug}/`.
- **Pages that change by themselves are not "broken"**: a shop shows
  random related products on every visit. The check asks the site a
  second time and sets aside only what the site varies by itself; an
  error, a redirect or a different page (a login wall) on the second
  visit sets nothing aside, and the rest of the page must still match. The figure
  says how many such pages there are.
- **A long number is no longer an "attack" on a text field**: a slug may
  be all digits; it is still tried on numbers, dates and lists.

Run the discovery again to get a map with the new slugs.

## For maps

- A type can list `rules`, kept by every field of the type; new rule
  `no_lookalikes` (`docs/map-format.md`).
- The review of a version flags a field that leaves its named type (a
  slug widened to text) as removing the type's pattern, rules and refused
  values.
