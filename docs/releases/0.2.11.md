# Equalizer 0.2.11 — visitors' requests only as actions, checked on the site

Install: `INSTALL.md`, with `git checkout v0.2.11` and `EQ_VERSION=0.2.11`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.11`. Updating from
0.2.10: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. One
database migration (`0025_unmapped_visitors.sql`, applied by panel-api on
start); no new setting.

The change went through two independent reviews; the findings are fixed
and tested.

## Changes you will notice

- **The discovery report shows a visitor's request only when you can act
  on it.** Every file or page option listed has the button **Add to a new
  draft**; nothing else is listed. Before, the report listed every file and
  path visitors were refused — scanners included — mostly with nothing to
  do.
- **The agent checks each one on the site first:**
  - a **file** is listed when at least two different visitors asked for it,
    it is of a harmless type (image, font, audio, video, stylesheet, PDF or
    office document) in a folder the map already serves, the site's own
    pages do not use it (those the agent handles itself), and the site
    really serves it. The button adds the type the site sends, which is
    what the gateway checks.
  - a **page option** (`?orderby=`, `?paged=`, a shop filter) is listed when
    at least two different visitors used it and the page really shows
    other content with it. An option the site ignores (`?test=1`), one that
    only redirects (`?author=1`) and any key that could make the site do
    something (`?add-to-cart=`) never appear; the agent never opens the
    latter.
- **"Asked by visitors, still missing" is gone:** it listed scanners'
  guesses (`/CFIDE/administrator`, `/crossdomain.xml`). The gateway's logs
  keep every refused request.
- **Visitors are counted once.** One visitor coming back every minute used
  to count as many; now the gateway sends a key made from the address with
  a secret only it knows (never the address, and the panel cannot turn it
  back), and the panel counts distinct keys. Counts from before the update
  count as one visitor until new reports arrive.

Reports of earlier discoveries keep their old lists, but their items are
not shown and cannot be added: run a discovery to get the new report.

## For operators

- Migration `0025_unmapped_visitors.sql` adds `unmapped_hits.visitors` and
  caps the old summed counts at one.
- The gateway derives the visitor keys from its form key
  (`secrets/form.key`): nothing to configure. Without a form key it uses a
  random one per process, and a visitor is counted again after a restart.
- Details: `docs/agent.md`, "Visitor requests"; `CHANGELOG.md`.
