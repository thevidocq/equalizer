# Equalizer 0.2.0 — the agent studies the site

The release for the first installations. Install: `INSTALL.md`, with
`git checkout v0.2.0` and `EQ_VERSION=0.2.0`; connectors
`ghcr.io/thevidocq/equalizer-connector:0.2.0`. Everything since 0.1.0 was
tested in the local end-to-end lab against ten real web applications.

## The agent studies the legacy site

- **Study with test accounts** (up to three, such as a customer and an
  administrator): each logs in with the site's own form and the pages behind
  the login are studied too. Accounts are sealed and erased at the end.
- **Read-only, guaranteed**: only `GET`/`HEAD` leave the agent (and the test
  accounts' logins); links and pages that act when opened are never
  followed; the lab proves every site's database is the same before and
  after a study.
- **A real browser** (Chrome) opens the pages behind the same guard: what
  their scripts load is studied too.
- **Form fields typed** from what their HTML declares (length, pattern,
  number, email, choices); fields that must accept free text are listed as
  still open, with the reason.
- **Administrations read-only** where the lab proved that viewing them
  changes nothing (Joomla, Drupal); WordPress's stays closed (it writes
  when its screens are only viewed).
- **Every draft is verified on the gateway** before you see it: each page
  opened directly and through the draft, compared (status, text, links,
  forms); every input tried with the attack set in dry-run. The score, the
  broken pages and the inputs still open show in the panel.
- **Self-correction**: what the verification finds broken is widened or
  sent back to the site area, what the values seen allow is narrowed; a
  change is kept only if the verification says it helps. The corrected
  draft is saved as a new version you approve as usual.
- **Profiles for ten web applications** (WordPress, Joomla, Drupal, Moodle,
  Magento, PrestaShop, OpenCart, TYPO3, MediaWiki, phpBB, plus a fallback):
  what each one proves is in `docs/compatibility.md`.

## Gateway

- Sites served with **their own certificate** (Site → Certificate), Let's
  Encrypt only for the relay and the panel.
- Hardened against hostile clients: request smuggling, huge headers, other
  hosts, too many form fields, forged client addresses, session floods,
  bodies sent at a drip.
- HTML fragments loaded by page scripts (Magento's templates) served as
  sandboxed assets; forms whose action carries a per-session value (phpBB)
  recognised.
- Measured cost: about 4 ms per page (`docs/performance.md`).

## Panel

- Discovery with test accounts; verification of any version with its
  score, broken pages and corrections.
- The site kind chosen at creation, ten kinds.
- The maps' decorative `risk` field is gone (stored maps are cleaned on
  start; old exports still import).

## Relay and connector

- Relay and panel hardened (guessed connector tokens, wrong panel
  passwords lock one account, cross-site writes, oversized bodies).

## Known limits

- Not yet tested on a real VPS with a remote connector, nor by an external
  penetration test.
- The administrations of the six newer applications stay closed to the
  agent (served by the site area).
- WebSocket not served (501); no virus scanning of uploads.
- Not available yet: SIEM forwarding, one legacy account per user behind
  OIDC, single sign-on to the panel, Kubernetes.

## Database

Migrations 0012 to 0017 run on start (`panel-api`); none can be undone.
Back up with `backup.sh` before upgrading.
