# Equalizer 0.2.35 — the same depth on every kind of site

Install: `INSTALL.md`, with `git checkout v0.2.35` and `EQ_VERSION=0.2.35`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.35`, source reader
`ghcr.io/thevidocq/equalizer-source-reader:0.2.35`. Updating from 0.2.34:
`INSTALL.md`, "Update", then `deploy/compose/check.sh`. No migration, no
new setting. Update the source reader too: the new readings are in it.

## Changed

- **The source reader reads every application's own request reader**,
  not only `$_GET` and the like: Drupal's (Symfony's `query->getInt()`…),
  MediaWiki's (`getInt()`, `getBool()`, `getText()`…), phpBB's
  (`variable('x', 0)`, typed by its default value), TYPO3's (Extbase
  `getArgument()`, `getQueryParams()`, `GeneralUtility::_GP()`),
  OpenCart's (`request->get[…]`), PrestaShop's (`Tools::getValue()`) and
  Magento's (`getParam()`, `getPost()`); an `(int)` in front types the
  field. A value read this way and then used in a query, a file or a
  command counts as a risky call, as with `$_GET`. Drupal's `.module`,
  `.theme` and `.install` files are read as PHP.
- **phpBB: the phpBB team's own extensions** (Board Rules, Pages…) are
  read as the site's; only `ext/phpbb/viglink`, which phpBB ships, is
  its core.

## Measured

- The efficacy study now covers seven kinds of site here (WordPress,
  Joomla, Drupal, generic, phpBB, MediaWiki, TYPO3), with the source code
  read, and puts the same measures side by side: every page the same on
  all seven (394 of 394), 99% served by a precise entry, every typed
  value closed (940 of 940, 880 of 880 with an extra key), no attack on
  the protocol through. One real extension per application shows the
  reader as deep on each as on WordPress plugins (`docs/efficacy.md`).
