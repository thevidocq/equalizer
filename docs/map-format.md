# Map format

The map is the gateway's single source of truth: **whatever is not declared
does not exist**. Schema: [`schema/map/gateway-map.schema.json`](../schema/map/gateway-map.schema.json).
Full example: [`schema/map/examples/permits-portal.yaml`](../schema/map/examples/permits-portal.yaml).

## Principles

- **Deny by default**: undeclared routes, parameters, forms and fields → 404
  or dropped; the legacy application is not contacted.
- **Rebuilding**: every request to the legacy application is generated from
  `legacy_request`.
- **Strict types**: every input value has a type and constraints. `text` and
  `file` are allowed only with `rules` or `scan`.
- **Authorisation in the gateway** (`roles`, `authz`, `scope`).
- **Provenance**: `origin` (agent/human), `confidence`, `risk`.
- **Immutable versions**, signed on publication.
- **Secrets outside the map**: only `vault://` references.

## Sections

| Section | Contents |
| --- | --- |
| `meta` | Schema, tenant, app, version, status, author, approver, `public_domain` (set by the panel: the host the map is served on) |
| `legacy` | `base_url`, `reach` (connector or direct, allowed destinations), login, expired session, error detection |
| `roles` | Role of unauthenticated visitors (`anonymous`), authentication on the gateway, legacy account per role |
| `defaults` | Rate limits, budget towards the legacy app, cache, string constraints, error template |
| `types` | Reusable types (`permit_id`, `tax_code`, ...) |
| `routes` | Read-only pages (`GET`): request to the legacy app, `render`, links, permissions |
| `forms` | Writes: typed fields, rebuilt request, outcome, limits |
| `flows` | Sequences of forms with server-side state |
| `api` | JSON endpoints for dynamic parts |
| `compat` | Historical URLs, served or redirected |
| `callbacks` | Inbound calls from third parties, with verification |
| `assets` | Static files served by prefix (CSS, images, scripts, fonts) with the allowed types |
| `external_links` | Allowed external domains |
| `behavior` | Behavioural thresholds |

## Reaching the legacy site

```yaml
legacy:
  base_url: https://permits.example-city.gov   # the site as its web server knows it
  reach:
    mode: connector
    connector_id: cn-srv-web01                 # one connector per server, of your tenant
    address: "127.0.0.1:8443"                  # where to connect (optional)
    allow: ["127.0.0.1:8443"]
```

- The host of `base_url` goes in the `Host` header and in TLS SNI: the web
  server picks the right virtual host. Links in pages that point to it are
  recognised as internal.
- `address` (optional) is where the connection actually goes, when it is
  not the host of `base_url`: a site moved to an internal listener, or an
  IP shared by several virtual hosts. It must be in `allow`.
- One connector serves every site of the servers it reaches. The panel
  refuses a map whose `connector_id` is not a connector of the same tenant,
  and the relay refuses it again at every request.
- `mode: direct` (the gateway connects itself) is accepted only towards the
  destinations the platform allows (`EQ_DIRECT_DESTINATIONS`, e.g. lab
  apps); customer sites always use a connector.

## Rendering

- `render: faithful` (default): the legacy HTML, transformed, with an
  identical look.
- `render: template`: a new view generated by the gateway; requires
  `template` and `extract`.

## Links and assets in pages

Faithful rendering rewrites every internal URL found in a page (`href`,
`src`, `action`, `srcset`, `<base>`, ...):

1. if it matches a route's `links` or a `compat` entry, it becomes the public
   route;
2. otherwise, if it matches the `legacy_request` of a GET route (same path,
   same query keys), it becomes that route: often there is no need to declare
   `links`;
3. if it is under an `assets` prefix, it keeps the same path;
4. otherwise it becomes a relative path, which the gateway rejects (404) and
   counts as an unmapped URL.

The legacy host never appears in the page. External URLs stay unchanged.
Assets are served only if the legacy `Content-Type` is among the prefix's
`types`; raster images are also checked against their real content. The
asset query string is never sent to the legacy application.

## Forms

A form is recognised in a legacy page by inverting its `legacy_request`: the
`<form method="post">` must post to the same path and query, and the hidden
inputs named in the body as `{{params.x}}` give the public action's
parameters. Example:

```yaml
forms:
  - id: permit_supplement
    route: /permits/{id}/supplement
    params: { id: { type: permit_id } }
    fields:
      message: { type: text, max_length: 1000, rules: [no_html] }
    legacy_request:
      method: POST
      path: /permits/supplement.do
      form:
        permitId: "{{params.id}}"   # read from the page's hidden input permitId
        text: "{{fields.message}}"  # the page's "text" input is renamed "message"
        state: "{{hidden.state}}"   # hidden input kept server-side
        kind: "SUP"                 # fixed value
    success: { body_contains: "Supplement recorded" }
    on_success: { redirect: permit_detail }
```

When the page is rendered:

- **every** hidden input of a POST form is removed from the page; the values
  the map uses (`{{params.x}}`, `{{hidden.x}}`) are sealed, with the page's
  charset, into a single `_eq_token` field (AES-256-GCM, valid two hours);
- the action becomes the public route, inputs take the public field names;
- the token is bound to a browser cookie (`__Host-eq_form`): a token taken
  from another browser is rejected (CSRF).

On submission the gateway accepts only `application/x-www-form-urlencoded`
bodies up to 1 MiB, rejects cross-site requests (`Origin`,
`Sec-Fetch-Site`), checks that the token belongs to this form and this
record, validates the declared fields (undeclared ones are dropped),
re-encodes every value into the legacy charset (a character the charset
cannot hold is rejected) and rebuilds the request. If `success` passes and
`on_success.redirect` names a route whose URL can be built from the form's
parameters, the visitor gets a 303 to it; otherwise the legacy answer is
shown with faithful rendering.

Not supported yet: `file` fields and `files` (the form answers 503), the
`cookie` success check (login), per-form rate limits. POST forms that match
no declared form keep working visually but post to a path the gateway
rejects.

## Login and sessions

With `roles.auth.provider: passthrough` the legacy login page stays exactly
as it is. The login is a declared form with `session.start`:

```yaml
forms:
  - id: login
    route: /login
    roles: [guest, citizen]
    fields:
      username: { type: string, max_length: 64, charset: "[A-Za-z0-9._@-]" }
      password: { type: password, max_length: 128, rules: [no_template_meta] }
    legacy_request:
      method: POST
      path: /login.do
      form: { j_username: "{{fields.username}}", j_password: "{{fields.password}}" }
    success: { cookie: JSESSIONID, not_contains: "Invalid credentials" }
    session: { start: citizen }
    on_success: { redirect: permits_list }
routes:
  - id: logout
    path: /logout
    roles: [citizen]
    legacy_request: { method: GET, path: /logout.do }
    session: { end: true }
```

How it works:

- **Legacy cookies never reach the browser.** When the legacy app sets a
  cookie (often already on the login page), the gateway creates a session
  and keeps the cookie there; it adds the session's cookies to every
  rebuilt request. The browser only holds `__Host-eq_session`, a random id.
- **Role.** A visitor has the `roles.anonymous` role until a form with
  `session.start` succeeds; then the session gets that role and a **new id**
  (no session fixation).
- **Success check.** `success.cookie` requires that the session holds that
  legacy cookie; `not_contains`, `body_contains`, `status` and
  `redirect_to` work as for any form. A failed login changes nothing.
- **Legacy expiry.** When `legacy.session_expired` matches (redirect to
  `redirect_to`, one of `status`, or `body_contains`), the role and the
  legacy cookies are dropped.
- **Logout.** A route or form with `session: { end: true }` deletes the
  session after the legacy answer.
- **Limits.** `defaults.session.idle_minutes` (default 30) and
  `absolute_hours` (default 12, restarted at login).
- **Storage.** Redis (`EQ_REDIS_URL`), shared by every replica; key = SHA-256
  of the id, content encrypted with AES-256-GCM. Pages of a session are sent
  with `Cache-Control: private, no-store`. If the store is unreachable,
  visitors are anonymous (restricted pages answer 403) and logins answer
  503.
- **`password` type.** Any printable character (the string defaults do not
  apply), at most 128 by default, never logged; like `text`, it needs at
  least one rule.

Not handled yet: legacy cookies are kept by name only (`Path` and `Domain`
are ignored), OIDC in front of the legacy login, per-user legacy accounts
from the vault.

## Rate limits and behaviour rules

Counters live in Redis and are shared by every replica (in process without
`EQ_REDIS_URL`). Keys hold only hashes of IPs and sessions.

- **`defaults.rate_limit`** applies to every page and form (not to assets);
  a route's or form's `rate_limit` applies on top. Values: `N/s`, `N/min`,
  `N/hour`, `N/day`, fixed windows.
- **Dimensions:** `per_ip`; `per_session` (the IP when there is no session);
  `per_user` (the session after login, the IP before).
- Over the limit: **429** with `Retry-After`, event `ratelimit.hit`; the
  legacy app is not contacted.
- **`defaults.legacy_budget.max_rps`** caps requests per second towards the
  legacy app across replicas (503 above it); `max_concurrency` stays per
  replica.

Behaviour rules (`behavior`):

| Signal | Counts |
| --- | --- |
| `distinct_param_values` | Distinct values of `param` (path parameter or query) on the route — enumeration |
| `failed_logins` | Submissions of a `session.start` form whose success check failed — brute force |
| `request_rate` | Requests to the route (or to every entry without `route`) |
| `missing_predecessor` | Accepted, not applied yet (logged at map load) |

When `threshold.count` is reached within `threshold.window` for the same
subject (`per`: `ip`, `session`, `user`):

- `throttle` (and, for now, `challenge`): 429 on that route until the window
  ends;
- `block`: 403 on the **whole site** until the window ends (event
  `request.blocked`, reason `behavior_block`);
- `alert`: one `behavior.alert` event when the threshold is crossed.

On routes the request that crosses the threshold is already refused; on
forms (the legacy app has answered) the rule applies from the next request.
If Redis is unreachable, limits are not applied (fail open) and the error is
logged every 10 seconds at most.

## Field types

| Type | Constraints | Default risk |
| --- | --- | --- |
| `int` | `min`, `max` | low |
| `enum` | `values` | low |
| `bool`, `date` | fixed format | low |
| `string` | `pattern` or `charset`, `max_length` | medium |
| `email` | format, `max_length` | medium |
| `text` | `charset`, `max_length`, `rules` (required) | high |
| `password` | `max_length`, `rules` (required); never logged | high |
| `file` | `mime`, `max_size_kb`, `scan` (required) | high |

## Rules for text fields

| Rule | Rejects |
| --- | --- |
| `no_html` | `<`, `>`, numeric entities `&#` |
| `no_sql_meta` | `--`, `/*`, `*/`, `;`, `\`, `"`, `` ` ``, NUL; the apostrophe is allowed only between two letters (`O'Brien`) |
| `no_template_meta` | `<?`, `?>`, `<%`, `%>`, `${`, `#{`, `{{`, `}}` |

An unknown rule makes the map impossible to load. Undeclared query
parameters are dropped; repeated ones are rejected. Without
`roles.anonymous` no page is public.

## Lifecycle

`draft` → `in_review` → `approved` → `published` → `retired`.

| Change class | Examples | Approval |
| --- | --- | --- |
| Widens the surface | New route/form, new role, less restrictive field, new `text`/`file` | Always, by a person other than the author |
| Narrows the surface | Route removed, tighter constraint | Automatic in automatic mode |
| Rendering only | Selectors, texts | Automatic in automatic mode |
| Behaviour and limits | Thresholds, rate limits, budget | Automatic if more restrictive |

The class is computed by the system from the diff, not declared by the
agent. An imported map arrives as a proposal and follows the same rules.

## Signature

The gateway reads a `SignedMap` document (see `schema/api/panel-api.yaml`):
`payload` is the base64 of the compact map JSON, `signature` is the Ed25519
signature of those bytes. The gateway only accepts maps with a valid
signature, `meta.schema` equal to `gateway-map/1.0`, `meta.status` equal to
`published` and `version` equal to `meta.version`. In the prototype maps are
signed with `eqtool sign`; later panel-api will do it.

## Notes

- In YAML the key `on` is read as a boolean: the map uses `target` instead
  (e.g. `authz.citizen.target: params.id`).
