# Equalizer 0.2.12 — the agent prepares, you publish

Install: `INSTALL.md`, with `git checkout v0.2.12` and `EQ_VERSION=0.2.12`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.12`. Updating from
0.2.10 or 0.2.11: `INSTALL.md`, "Update", then `deploy/compose/check.sh`.
The database migration of 0.2.11 (`0025_unmapped_visitors.sql`) is applied
by panel-api on start if it is not there yet; no new setting.

Everything changed went through independent reviews; the findings are
fixed and tested.

## Changes you will notice

- **No more buttons for visitors' requests: the agent puts what it has
  checked straight into its draft.** A file or a page option visitors
  asked for goes in only after the agent has checked it on the site (the
  rules of 0.2.11: at least two different visitors, a harmless file type
  the site really serves, a page option that really changes the page). It
  is listed in the report under **Added from visitors' requests**, with
  the reason: look at it before publishing, and take out of the draft what
  you do not want. Publishing stays yours.
- **A page option goes in only with the values the site itself offers** —
  the choices of its menus and links (`?orderby=price`, `?orderby=date`),
  the same on every page that offers them, or a whole number for page
  numbers and for prices the site offers as whole numbers. Any other
  value, an attack included (`?orderby=1 AND SLEEP(5)`), is refused. An
  option whose values the site does not offer, or offers differently from
  page to page (a filter whose choices change with the category), does
  not go in: visitors with a value the map lacks would get an error.
- **Email when a draft is ready.** Once the agent has checked (and, if
  needed, corrected) a discovery's draft, the administrators get one email:
  what changes, what came from visitors' requests, the agent's check and
  the link to the draft. Nothing when a discovery finds nothing to change.
  It is a new kind in **Settings → Alerts** ("A discovery's draft is
  checked and ready to publish"), on by default. With **continuous
  discovery** this is the whole loop: the agent studies the site every day
  or week, and you only open the email and publish.

## For operators

- `POST /v1/apps/{app}/discoveries/{id}/adopt` (0.2.11) is removed.
- The draft email needs the platform's mail server (`EQ_SMTP_ADDR`), as
  every alert; it is sent in the background, so a slow mail server never
  holds the agent. Every SMTP exchange now has a deadline.
- Details: `docs/agent.md`, "Visitor requests"; `docs/manual/tenant.md`,
  "Alerts"; `CHANGELOG.md`.
