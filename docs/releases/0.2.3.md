# Equalizer 0.2.3 — hardening and the site's reach

Install: `INSTALL.md`, with `git checkout v0.2.3` and `EQ_VERSION=0.2.3`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.3`. Updating from
0.2.2: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. No database
change needs attention beyond the migrations panel-api applies on start.

## Changes you will notice

- **Change the reach from the site page.** How Equalizer reaches a site —
  through a connector or directly, which connector, which address — is now
  changed from **Site → Isolation**, under *How Equalizer reaches this
  site*, without rerunning discovery. The current map is republished with
  the new reach and your tuned entries are kept. The first reach is still
  chosen when discovery runs the first time.
- **Mobile menu.** Opening a dialog (such as "Protect a site") from the
  phone menu now closes the menu, and dialogs sit above it.

## Hardening (no visible change, but important)

The request-rebuilding code — the part that rebuilds every request so no
client byte reaches the legacy application — was hardened and fuzzed:

- areas with roles could be stepped around with paths that legacy servers
  read as the protected one (`//admin/`, `/admin;x/`, `/admin./`,
  `/Admin/`); entries and areas are now matched on the path as servers read
  it, and case-ambiguous paths are refused;
- JSON with invalid UTF-8, an unpaired surrogate escape, or a key written
  twice is refused instead of being silently altered;
- multipart field and file names are written as browsers write them;
- XML processing instructions other than the declaration are dropped.

Fuzz tests on query, JSON, XML, multipart, path matching and JSON text run
in CI.
