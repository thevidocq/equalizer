# Equalizer 0.2.31 — every CMS in the source reader, maps for other tools

Install: `INSTALL.md`, with `git checkout v0.2.31` and `EQ_VERSION=0.2.31`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.31`, source reader
`ghcr.io/thevidocq/equalizer-source-reader:0.2.31`. Updating from 0.2.30:
`INSTALL.md`, "Update", then `deploy/compose/check.sh`. No migration, no
new setting.

## New

- **The source reader knows every CMS Equalizer supports.** Besides
  WordPress: Drupal (8 and later, and 7), Joomla, Magento 2, PrestaShop,
  OpenCart, TYPO3, MediaWiki, phpBB and Moodle. For each it reads the
  entry points the way that application declares them (routing files,
  components, controllers, web services, special pages, AJAX services),
  studies only the extensions and the site's own code, and takes from the
  core only its version, without even reading it. It finds the
  application in a folder too (WordPress in `/blog`, Drupal in `/web`,
  Moodle 5 in `/public`). The report groups everything by extension and
  shows the query that selects an entry point (`option=com_shop`).
- **Download a map in four formats**: YAML and JSON (the map, to import
  again), OpenAPI 3 (what the map accepts, for API tools) and
  ModSecurity / Coraza rules (deny by default, for a WAF). The rules keep
  the checks, not the rebuilding: their comments and the guide say what a
  WAF loses.
- **The assistant can narrow a field**: a free-text field of a page or a
  form becomes a number, a date, an email, a list of values, yes/no,
  digits, a slug, a key or shorter text, as a draft the agent checks on
  the site. It no longer offers what it cannot do, and a long answer is
  no longer cut in the middle of a sentence.

## Fixed

- A shop that shows random related products (WooCommerce) no longer has
  pages reported broken by the check of a draft, nor sent back to the
  site area by its correction.
- The discovery report shows Built with, Coverage, Pages found and Kept
  out above **Check on the site**.
- Source reader: the install command quotes a folder with spaces; the
  whole disk and system folders are refused; a reader installed before
  0.2.30 reads its folder again; heredocs, attributes, closures on hooks
  and `Foo::class` are read right; CodeIgniter's `libraries/` is the
  site's own code.
- A source read no reader takes, or a scan the scanner never started, no
  longer blocks the site's next read or scan for good: it fails with the
  reason (a read nobody takes after 15 minutes, one running after an
  hour; a scan never started after 5), and a new reader token ends
  the old one's reads.
- The Security tab shows the draft built after a scan even when it comes
  an hour later (while a version was in review), without reloading.
- Renaming a site in the same request as a refused change no longer
  renames it.
- A browser error without a message no longer stops a discovery.
- A check of a draft stopped by a lost agent no longer keeps its last
  progress line; an agent setting that is not a number falls back to its
  default instead of stopping the agent.

## For operators

- Nothing to do for a source reader installed with 0.2.30. One installed
  with 0.2.29 keeps working; its Source tab's new command mounts the
  site's folder at its own path.
- The efficacy study passed on every lab site (`docs/efficacy.md`).
