# Equalizer 0.2.7 — a parallel domain in front of a site behind a CDN

Install: `INSTALL.md`, with `git checkout v0.2.7` and `EQ_VERSION=0.2.7`;
connectors `ghcr.io/thevidocq/equalizer-connector:0.2.7`. Updating from
0.2.6: `INSTALL.md`, "Update", then `deploy/compose/check.sh`. No database
change.

## Changes you will notice

- **The site is asked for the right name.** Equalizer sends the legacy site
  a name (`Host` and TLS name) and checks its certificate against it. Until
  now it was always the site's public domain. Now, in direct mode with a
  **name** in the address (`www.example.com:443`), Equalizer asks for that
  name — what a site behind Cloudflare or another CDN needs. With an IP, or
  through a connector, nothing changes. No new choice to make.
- **A parallel domain works.** You can protect `test.example.org` in front of
  `www.example.com` (even behind Cloudflare) while the original stays as it
  is: create the site with the test domain and give `www.example.com:443` as
  the direct address. Step by step: manual, *A parallel domain, to try a site
  without moving it*.
- **Advanced: "Name asked of the site".** Optional, under *Advanced* in the
  reach form (first discovery, template, Site → Isolation), for a site that
  answers to yet another name. Leave it empty otherwise.
- **Clearer direct-mode notice.** It now says plainly that it shows the
  address Equalizer connects from, to allow on the site in production — not
  needed for a test.

## For operators

- After the update run `deploy/compose/check.sh`.
- If the panel is behind Cloudflare, set `EQ_OUTBOUND_IPS` to the VPS
  address (`curl -4 ifconfig.me`): otherwise the notice shows Cloudflare's
  addresses.
- `EQ_DIRECT_DESTINATIONS` entries need a port (`host:port`); a malformed one
  stops `panel-api`. A public site reached directly does not need it.
